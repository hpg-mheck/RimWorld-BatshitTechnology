## Test justifications

The Tractor Bomb follows the same split. Its pure logic is in Core with
unit tests (TractorBombYield: the Dial-A-Yield clamps and slider stops;
TractorBombTiming: the protest, flip, countdown roll, cap, lamp and
beeps; DeathVortexMath: the death's parts and sputter), and XML tests pin
its defs, research and textures. The robot's AI, the emplaced bomb, the
death vortex and the gizmos need a live map, so the smoke runner's
TestTractorBomb scenarios cover them instead; drawing (the flip frames,
the vortex, the lamp, the sliders' look) is checked by eye. The flee
step's arithmetic (TractorBombFlee: the flee distance, the too-close
test, clear destinations, the line pick) is unit tested; its job giver,
drivers and destination search need a live map and real think trees, so
the smoke runner's TestTractorBombFlee covers them, and XML tests pin
the patch against RimWorld's own think trees and races.

The Tractor Barn and the decisions taken after the core build follow it
too. Their arithmetic is unit tested in Core (TractorBarnRepair: who
goes home, step costs, per-injury steps; TractorBombApproach: the
dispositions' stops). The barn's bills, its hauling, its forming and
docking, the Disposition button, a planted bomb's reaction to a hit
(PreApplyDamage, stage changes on its own tick) and the barn's death
need a live map, real pawns and real projectiles, so the smoke runner
covers them (SmokeTest.TractorBarn.cs, TestTractorBombDispositions,
SmokeTest.TractorBombHits.cs, TestDeathBlasts), each check proved to
fail by a sabotage run; XML tests pin the barn's defs and the
stopgap's removal; the barn's art is checked by eye at full size and
downsampled.

Comps, buildings and job drivers depend on RimWorld's runtime (map, ticks,
power nets, Unity), so they are not unit-testable in this project. They are
covered instead by: Def validation against the real game assembly
(Tools/validate-defs.ps1), the XML regression tests, and the in-game smoke
test (Tools/smoke-test.ps1). Pure logic lives in BatshitTechnology.Core with
unit tests (WeightedSelector, ReactorHeat, MonologuePicker, BallistaPower,
MagazineNetwork, BlastSchedule).

AnyRim follows the same split. Its geometry, site scoring, palettes, def
catalogue and texts are pure Core code with unit tests (TownGeometryTests,
TownPlanTests, TownSiteTests, AnyRimTextTests, TownDefsTests). The game
side (Source/AnyRim.cs, AnyRimResidents.cs including
JobGiver_AnyRimSeekSafeTemperature, MapComponent_AnyRim.cs, and the
Showcase hooks) needs a live map, so it is covered by the smoke runner's
TestAnyRim checks and by the showcase's TOUR capture instead.
